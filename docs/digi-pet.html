digi-pet

A virtual pet that lives above your Claude Code prompt. It eats your prompt cache: let the cache go cold and it gets hungry, yells, and eventually gets sick.

Drag the slider to move time since your last prompt, or press Play. Then send it a prompt and watch it eat. Everything here follows the plugin's own rules.

In the real plugin the pet is a Digital Monster Color Digimon. It hatches from a random egg, one of the five device versions, and grows from how you work: turns, tests, commits and care. This page uses an original stand-in sprite so it can be shared.

It eats your prompt cache Built

Claude Code keeps your conversation in a prompt cache for an hour after each request. Sending the next prompt inside that hour reads the cache at about a tenth of the normal input price. Missing it means the whole conversation is written to the cache again at about twice the price. On a 150k-token session that is roughly a 20× difference for the same prompt.

Every request in the main conversation counts as a meal and resets the clock. The pet gets hungrier as the hour runs out, so you notice before the cache goes cold, while a prompt can still save it.

At 60 minutes the cache is cold. The pet stops yelling, because there is nothing left to save. The TTL is a setting: set it to 5 if your sessions use the default 5-minute cache.

When it stays quiet Built

A cache going cold while you are at lunch or done for the day is fine, so the pet does not nag then. During rest hours it naps on a dark screen.

No pointless alarms

If a rest window starts before the cache would go cold, there are no warnings at all. A prompt at 11:20 makes the cache last until 12:20, inside lunch, so feeding it at 12:05 would only move the expiry deeper into lunch. Try the 11:20 and 17:10 presets above.

Ways to turn it off

/digi break 90m or /digi break until 15:30 for a meeting. /digi sleep when you are done with a session. /digi side for side work, or list side-work folders in settings. Small sessions under 20k tokens of context never get hungry, since their cache is cheap to rebuild.

Care mistakes Built

On the original V-Pet, ignoring a hungry pet was a care mistake, and care mistakes decided what it grew into. Here a care mistake is coming back to a cold cache on the same working day, when nothing excused it. The pet looks sick for three turns and the mistake goes on its record. It never dies and never de-evolves.

Above your prompt Built

The pet sits at the right edge of the band above the prompt. It is always there, and it shows what Claude is doing. While Claude works, the rest of the band becomes a battlefield. Small monsters walk in from the left and the pet shoots them down, two lanes at a time while a tool runs. When a test, build or lint run fails, a big red boss takes the field and stays until that check passes again; then it blows up with a WIN! and the win counter goes up. That counter is real: it shows this stage's battles won. When a long prompt leaves the band fewer than eight rows, the pet shrinks to a four-row half-size screen, and to a single line while a slash-command or file picker is open.

One turn Built

A turn is one exchange: you send a prompt, Claude works on it, and Claude finishes answering. However long the work runs, it is one turn. Inside it, every request Claude sends to the model is a meal for the hunger clock, so a busy turn can be one turn and twenty meals.

You: "fix the failing test"→ request→ Read→ request→ Edit→ request→ Bash: npm test→ request→ Claude: "Fixed it."

How a battle happens Built

A battle starts when a check fails: a test, build, type-check or lint run that Claude makes. The battle is won if the same check passes again before the turn ends, and lost if it is still failing when the turn ends. A check that passes without failing first is no battle, just two DEF points. Which commands are checks

npm, pnpm, yarn or bun with test, build, lint, typecheck or check; jest, vitest, pytest, tsc, eslint, ruff, mypy, go test, cargo test, xcodebuild and a few more. Background runs are skipped, since they return before they finish.

How it knows a run failed

From the output, not the exit code. Claude usually pipes test output through tail, which hides the real exit code: 96% of your test runs were piped. So the plugin reads lines like 2 failed, FAIL, error TS2322 or (3 errors,. ESLint warnings alone are a pass.

Battles matter from Champion on. To reach Ultimate and then Mega the pet needs 15 battles in its stage and an 80% win ratio. The battle count starts over at each stage; the win ratio counts every battle ever, as on the device. Between 40% and 79% it gets one chance a day, better the closer it is to 80%.

Risky moves turn it Virus

A forced push, --no-verify, git reset --hard, an rm -rf outside temp and build folders, or an interrupted turn. Five a day across a stage send a branching pet down its Virus branch: Koromon to Betamon, Agumon to Devimon.

Trophies need proof

A commit counts when its output shows [main 1a2b3c4], a pull request when the output has its link. A commit that found nothing to commit, or a hook that failed, earns nothing.

Past 20 points in a day a stat grows at a quarter of the speed, and tokens or cost never raise one, so the pet never rewards spending more. The stats are a scoreboard: the branch comes from the chart's rules above.

Which parts are the device's and which are ours: the branch rules, the 15 battles and the 80% are the device's. How long each stage lasts, the commit and subagent gates, risky moves turning a branch Virus, the daily chance below 80%, the jogress partner on call, hatching keeping its turns, weight in grams and the SYN bonuses are this plugin's own, and all of them can be tuned.

digi-pet is a personal Claude Code plugin built on Claude Code's function-hooks plugin API. The Digimon sprites it uses are Bandai's: idle frames from the Digital Monster Color, and full twelve-pose sheets for 87 of the 90 species from the community Full Color Digimon Dot Sprites pack. They stay on your machine.
